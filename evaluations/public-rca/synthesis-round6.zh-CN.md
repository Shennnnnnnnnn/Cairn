## 结论：预算影响很大，新版的准确率优势尚未超过旧版

十二次均自然结束、保存三份交付物并通过独立复算。原生 Pi 联合标签命中 3/4，两版 Cairn 均 4/4。Pi 在内存例正确定位了 cartservice2-0，却把 `disk_io` 排在 `memory` 前，因此本轮出现 1/4 的错误完成；数值验收没有拦住这个分类错误。

十二次累计输出都超过原来的 24,000 阈值；两次单回复输出超过 8,192；没有一次超过原来的 720 秒总时限。上一轮首次完成受输出限制影响很大，不能直接据此判定 harness 无效。三层限制同时解除、每条件仅一次且模型路径不同，不能单独量化每种限制的因果贡献。与上轮“含必要恢复”的最终结果比较，新版正确交付从 3/4 到 4/4，旧版仍为 4/4，Pi 仍为 3/4；Pi 多交付的一例并未让总命中数增加。

新版累计执行 1578.22 秒，旧版 1424.01 秒，Pi 1436.49 秒。新版比旧版多用 10.8% 时间，已记录 token 多 14.2%（16,714,857 对 14,630,208；Pi 10,416,831）。三组 token 均为下界：Pi、旧版、新版分别出现 2、3、1 次连接错误，由 Pi 原生请求重试后继续，失败请求的真实消耗未知。不能把这些记录值的比例换算成金额比例。新版本轮记录 token 约为上轮含恢复记录值的三倍，金额未知；放开预算解决截断，也放开了较长的探索与重复校验。

小型 finish 已正常工作：两版各四次 finish 均一次通过，无拒绝；新版声明参数合计 2244 字节，旧版 6838 字节，减少约 67.2%。这不等于端到端模型成本下降，本轮新版输出 token 反而比旧版多约 10.7%。两版各有九次含 Finding 的 checkpoint 状态更新（发现可包含观测、假设和问题）、四例都保存过事实，成功的仅摘要 checkpoint 均为零。

新版生成 22 份交接快照，其中 4 份是创建时的空快照、18 份含事实引用；旧版没有独立交接包。八份状态副本的基础重载全部通过，两版均保留目标、约束、事实并推进 owner epoch。含已存发现引用、持久详情、报告及原生会话定位的交接材料完整性为旧版 0/4、新版 4/4；旧版仍能从图和产物重载，不能说它没有恢复能力。新版重载 context 为 11,359–12,117 字节，全部低于既有 16 KiB 检查线。这里验证的是保存材料与来源可读，尚未验证新模型真正接管并完成任务；本轮没有主动中断，不能计算模型超时恢复率。

事实保存仍不稳定：新版内存例首次 checkpoint 在 187.29 秒、累计输出 27,328 token 时才出现；旧版网络例为 216.07 秒、36,173 token。无预算最终能保存，不代表前段被中断时已有可用事实包。模型接口收窄与模型及时调用，是两个不同的问题。UI 中网络例的终态交接还保留“检查单个 pod、再构建交付物”的旧 next，即使摘要已经写明交付物完成；来源材料齐全没有验证这段行动建议是否过时。

标签命中也没有消除正文问题。旧版 CPU 报告把长期约 46% 的 adservice-grpc 成功率概括为全为 100%；Pi CPU 报告把节点写速率 88 的时点从 7460 写成 7280；Pi 网络报告将含下降的序列称为单调，再用负差分抵消正计数。新版 I/O 报告引用了不存在的 `system.io.iowait` 名称，网络报告把未提供的调用拓扑写进依赖关系表和部分“直接观测”。各组仍有从非单调性推断区间单位、把相关性写成机制解释的情况。逐例审阅保留这些缺口，主表只沿用冻结的完成、复算与标签口径。

范围检查另有实际限制：补充审阅发现 8/12 次运行、12 条命令使用了工作区之外的通用 `/tmp` 文件名，违反本次 cwd-only 指令。命令显示在读取前覆盖输出或复制自己的脚本，未观察到读取其他案例证据或隐藏评分；原始 CSV 哈希全部保持。但临时文件名跨案例复用，且没有 OS 沙盒，严格隔离并不成立。原有 53 项显式文件参数检查、436 条命令关键词扫描的零标记，不应冒充完整隔离证明，见补充审计。

这次支持保留小型接口、增量事实和宿主交接的方向；它没有证明新版更准或更省。后续最值得处理的是首次事实保存偏晚、交付齐全后的重复核对，以及临时文件的工作区边界。通用运行时继续保存可核对的状态，领域单位、调用关系和因果判断需要明确来源与独立审阅。
