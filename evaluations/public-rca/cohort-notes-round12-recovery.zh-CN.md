# Round12 批次口径补充

原始冻结协议中“历史服务故障 cohort”的简写，统一解释为“**含故障时段的原始 Pi36 cohort**”。旧 GLM 队列持续运行并跨越用户报告的服务恢复时点，原批次也有成功尝试；不能将整批36次都归类为服务故障或恢复前请求。原协议及其哈希原样保留，这份补充不修改任何 actor 结果、评分条件或原始记录。

修订主表使用恢复后完整重测的 Pi36，加原始 Sol18，共54次；原始 Pi36单列，全部90次和3个原始付费探针成本均保留。新 GLM 等旧 GLM 全部18次结束后再开始，新 DeepSeek 在旧 DeepSeek 全部结束后开始。两批时段、排队及服务可用性差异必须披露，等待旧lane的时间不计入单个actor耗时。

同一 sessionRef 匹配只说明身份续接，不能称为恢复成功。分别记录收尾阶段是否正常结束、workflow是否完成、产物是否通过验收、根因是否正确以及是否有效交付。若前阶段没有有效工具／输出，收尾阶段又执行新的分析，则称“同会话重新推进”，不能称找回或单纯保存此前事实。所有相关阶段成本计入。

生产 CLI adapter 在冻结后修复了不透明模型 ID 的传递。正式评测使用冻结 Scheduler 与独立真实宿主 driver，显式传 provider 与完整模型 ID，没有调用该生产 adapter。正式快照完整性和当前工作区的后续变化分开核对，不将工作区新构建冒称为本轮被测版本。
