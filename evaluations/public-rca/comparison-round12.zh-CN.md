# Round12：可选薄调度层与三模型复测

**结论：薄调度层已落地，真实的“验收拒绝→Reason→Explore修复→Reason审核→完成”闭环已经跑通，但没有证据说明它普遍提升准确率或成本稳定性。** 本轮 DeepSeek 两组均正确并完成9/9，Cairn记录tokens少24.3%；Sol两组均正确9/9，Cairn完成率降到8/9、tokens多36.6%。恢复后的GLM18次均遭遇服务终止，不能据此比较其推理能力。自动调度继续保持显式启用，默认五工具路径不变。

本轮实际运行用户最后限定的三个组合：Pi＋global:deepseek-v4.1-flash、Pi＋cn:glm-5.3、Codex＋gpt-6.1-sol。沿用三道公开开发题，每题每模型三次、原生与新版 Cairn 两组，共54次。用户报告Pi服务恢复后，新增完整Pi36次，原54全部保留。主表为新Pi36＋原Sol18，历史Pi36单列，总计90次尝试＋3个原始探针；Sol与付费探针未重跑。新Pi各lane等待同模型旧lane结束后启动，跨批每模型最多一个活跃原生会话，无评测时间、token、调用数或探索轮数预算。

正式快照为round12-final。三个探针保留原round12快照及全部成本，未付费重跑；仅可信评测runner在正式运行前补齐全局取消传播和停止后续actor，核心src／dist／skills与原探针版逐字节一致。版本边界与原始哈希见probe-origin.json。

新版 Cairn 在调用模型之前保存唯一通用任务，通过真实 Scheduler 自动执行 Bootstrap／Reason／Explore／Conclude，执行仍由同一原生宿主完成。各模型阶段不加载 Cairn 五工具；持久黑板、分支租约、提交审核、宿主验收和下一阶段调度由可信宿主实现。调度 owner 使用独立 mcp 身份，每个真实模型 session 单独记录。

原始GLM中另有4个任务被最终原始JSON协议阻断，1个任务提交`supported/refuted`事实却缺依据或引用而被拒绝；部分任务的文件合同和数字已经通过，不能概括成没有完成分析。严格验收防止把它们记为完成，同时也暴露了结果接入与纠错不足。

## 工程结论与下一步

可保留这层显式启用的通用Scheduler：它复用宿主、持久化真实增量、隔离分支提案并重新审核覆盖，没有新增模型服务或排障专用算法。与原版相比，当前实现是阶段／批次交替调度；不是完整的外部进程监督器，也不能在每次原生工具执行后自动保存尚未返回的事实。默认五工具方案继续适用于希望由当前会话自主推进的接入。

下一版优先处理三个通用边界，以下为未实施建议：

1. **让阶段输出契约与运行时一致，并提供原会话纠正反馈。** 从schema生成长度和条件约束，覆盖原始JSON、引用长度及supported/refuted依据要求；保留已取得的产物和结果候选，再请求明确修正，避免错误地重做探索或放宽验收。
2. **减少无效阶段和重复上下文。** 只交接事实增量、变化文件和当前验收缺口，按实际缺口安排验证；避免轻微描述修复扩展为大量低收益回归。对首个工具前的服务失败先识别无新增事实，不把重复Conclude当作成功恢复；仍保留后续显式恢复入口，不引入案例预算或模型特判。
3. **把语义质量验证做成可选宿主能力。** 通用核心保留来源、单位原值、时间与缺测声明；领域验证器可检查采样顺序、单位换算、覆盖集合与叙述一致性。数字可复算、任务完成和独立结论正确性继续分别展示，不能以关键词或特定排障标签替代事实审核。
