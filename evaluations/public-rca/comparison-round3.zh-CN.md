# 第三轮公开案例复验：产物验收与分层交接

实验日期：2026-10-17（Asia/Shanghai）。对应工程实现第四轮，正式运行 ID：`2026-10-17-aiops2022-round3c`。旧版对照为 `2026-10-16-aiops2022-round2b`；原报告保留在 [第二轮比较](comparison-round2.zh-CN.md)。

**两项优化已经落地，完成状态、产物可复核性和交接可追溯性改善；根因联合正确率没有提高。** 新 Cairn 仍为 2/4，具体对象命中从旧轮 4/4 降为 3/4，错误完成的绝对数量仍为 2。四例全部通过了文件契约与数值复算，说明这个验收器能约束交付，却不足以判断根因。现阶段应把 Cairn 定位为帮助宿主管理证据、交付与接管的通用 harness，不能据这组结果宣称它提高了模型排障准确率。

## 主阶段结果

| 指标 | 旧 Cairn | 新 Cairn | 同轮原生 Pi |
| --- | ---: | ---: | ---: |
| 首选具体对象命中 | 4/4 | 3/4 | 4/4 |
| 首选对象＋故障大类联合命中 | 2/4 | 2/4 | 4/4 |
| 运行完成（见下文口径） | 2/4 | 4/4 | 3/4 |
| 根因错误的完成 / 全部运行 | 2/4，50% | 2/4，50% | 0/4，0% |
| 根因错误的完成 / 已完成运行 | 2/2，100% | 2/4，50% | 0/3，0% |
| 文件契约＋独立数值复算通过 | 未实施相同检查 | 4/4 | 2/4 |
| 进程超时 | 2/4 | 0/4 | 0/4 |
| 输出预算停止 | 0/4 | 0/4 | 1/4 |
| 合计耗时 | 2345.95 秒 | 1657.67 秒 | 2066.26 秒 |
| 已记录总 tokens，含缓存读取 | ≥1,819,406 | 2,294,918 | ≥1,628,378 |
| 输出 tokens | 64,942 | 63,845 | 82,007 |
| 原生 / Cairn 工具请求数 | 73 / 15 | 82 / 25 | 95 / 0 |

Cairn 的“运行完成”要求任务为 completed、当前 owner epoch 的验收通过且提交文件与验收快照相符。Pi 为正常进程退出、无时间／输出预算停止且保存有效 `answer.json`；其原生流程没有 Cairn 完成状态，数值验收在进程结束后独立执行。两者完成口径不同，表中单列；“错误完成”只按比赛对象＋大类判断，不把数值或文件缺陷混为根因错误。工具计数是声明的请求数，预算停止前声明的写文件调用可能尚未执行。

新 Cairn 比旧轮观察耗时减少 29.3%，比同轮 Pi 减少 19.8%；输出 tokens 比旧轮减少 1.7%。旧轮两个正确答案最终停在 active，新轮四个任务均完成，所以“已完成中的错误率”下降；**错误完成 / 全部运行仍为 50%，不能解释成少犯了一半错误。**

## 四例发生了什么

| 案例 | Pi 首选 | Cairn 首选 | Pi / Cairn 文件与复算验收 | 主阶段秒数 Pi / Cairn |
| --- | --- | --- | --- | ---: |
| case-01 | `node-6.recommendationservice2-0` / `disk_io`；正确 | `node-6.recommendationservice2-0` / `disk_io`；正确 | 通过 / 通过 | 397.6 / 513.7 |
| case-02 | `node-6` / `cpu`；正确 | `node-6` / `cpu`；正确 | 通过 / 通过 | 532.6 / 341.5 |
| case-03 | `node-6.cartservice2-0` / `memory`；正确 | `node-6.cartservice2-0` / `disk_io`；错误 | 指标名不精确 / 通过 | 477.4 / 332.5 |
| case-04 | `productcatalogservice-grpc` / `network`；正确 | `node-5` / `network`；错误 | 缺 REPORT.md / 通过 | 658.6 / 470.0 |

- **写 I/O（case-01）**：两组首选均命中。Cairn 的七次摘要式 finish 缺少实际发现与提交物，随后一次实质提交因两个指标名称不精确被独立复算拒绝，修正后通过。类别在验收反馈前已是 disk_io，因此不能把与旧轮的类别变化归因于复算反馈。Cairn 报告还把 CPU 节流描述为无异常，原序列中 throttled_seconds 均值实际从 1.7982 升至 18.5721；它不在声明的 checks 中，验收未覆盖该排除论据。
- **节点 CPU（case-02）**：两组均定位 node-6/cpu。Cairn 在 341.5 秒内完成，旧轮此例超时。三个声明的数值检查通过；“更早尖峰属于启动”等解释缺少环境证据，不因均值复算而成为事实。
- **容器内存（case-03）**：Pi 定位正确，但一个磁盘读指标漏了设备后缀，七项复算中的一项无法对应准确源序列，因此组合验收失败。Cairn 对象正确却判成 disk_io，五项声明数字均能复算。它用当前内存均值约 64.15 MB、低于 128 MB limit 下调 memory，忽略了历史 max-usage 水位已达 128 MB、failcnt 增长和缓存回收的联合反证。历史水位达到 limit 不代表当前采样持续占满 128 MB。
- **服务网络（case-04）**：Pi 主阶段已保存正确的 productcatalogservice/service/network 答案，但在输出预算停止前未完成 REPORT.md。Cairn 完成并通过五项数值检查，首选却是 node-5/network，误把节点异常当成注入对象；真实服务对象也不在前三。冻结的服务后缀等价规则不能把 node 自动改为 service。最大的节点错误计数和下游时延不能单独确定故障注入层级。

八份主阶段输出均已独立语义复核，见 [qualitative-audit.json](runs/2026-10-17-aiops2022-round3c/qualitative-audit.json)。两组都存在尚未证实的指标物理单位、采集口径或因果推断。数值复算只核对声明的序列、窗口和统计，不替模型选择完备反证，也不证明全文正确。

## 恢复和交接

正式八轮中没有进程达到 720 秒；只有 Pi 的 case-04 触发输出预算停止。24000 是在完整模型回复后检查的软阈值，因此该例已记录输出为 25889。全新原生会话在同一工作区追加 180 秒预算，用 **142.78 秒、83480 tokens** 补齐报告，独立文件与六项数值检查通过。首选正确答案保持不变：这是交付恢复与正确结论保留，纠正错误诊断数为 0。恢复消耗不计入主表。

Cairn 四例没有自然停止，不存在本轮实际恢复成功率的分母。为验证持久化交接机制，另以 SQLite backup 复制四份已完成的真实数据库，在副本上显式重开、换会话接管：**4/4 通过**。每例检查目标／来源／约束保留、owner epoch 推进、旧验收不复用、focus 相关旧前提、交接报告与原会话定位、提交文件不变及原数据库未变；恢复 context 为 8157–10083 字节。见 [handoff-restoration.json](runs/2026-10-17-aiops2022-round3c/handoff-restoration.json)。这是无模型的状态重载检查，不是强制断线或自然超时后的模型恢复实验。

真实模型共保存四个 handoff key、五条追加记录，关联四份 `EXPLORATION.md`；一例同 key 更新两次。它们都通过 finish 在收尾时保存，没有观察到探索中途调用 checkpoint。这证明最终交接材料能够落盘、定位和重新读取，尚未证明遇到中途断线时减少重做。报告与会话是定位引用；handoff 本身不授予验收条件覆盖，也不是不可变内容快照。

## 成本口径

| 主阶段 provider usage | 新 Cairn | 同轮 Pi |
| --- | ---: | ---: |
| input | 144,161 | 173,699 |
| output | 63,845 | 82,007 |
| cacheRead | 2,086,912 | 1,372,672 |

Reasoning tokens 已包含在 output，不能重复相加。Pi 输出停止时仍可能有未结算 usage，因此合计是下界；旧 Cairn 也有中断下界。当前没有可靠的 provider 计费单价，配置中的 0 不能解释为免费，不能据总 tokens 或耗时推断金额节省。

新 Cairn 额外出现 15 次 incomplete finish 和 1 次参数错误，共 16 次被拒绝的完成请求。拒绝帮助暴露了未交付文件、指标名错误及 Finding 参数混淆，但反复摘要式提交也造成摩擦；下一轮应优先减少这类误用。缓存读取累计量更高，尚无整体 token 成本下降证据。

两次开发试运行也有实际消耗，均排除于主比较：`round3` 因源文件归属、owner epoch 与计数器边界问题中止；`round3b` 因仅凭名称强制推断累计计数器口径的评测规则中止。修复后 `round3c` 从全新工作区重跑全部八轮，没有复用单例结果。排除的四个部分运行共 **1079.01 秒、至少 855376 tokens**，详见 [excluded-trial-costs.json](runs/2026-10-17-aiops2022-round3c/excluded-trial-costs.json)。主比较、一次恢复及两次排除试运行合计已记录 **至少 4862152 tokens**；不含无真实模型的自动化测试。

## 实验边界和复现

沿用公开 AIOps 2022 同一天／同一测试床的前四个故障切片，仍是原始指标离线分析，没有实际部署系统、注入故障或在线修复。Pi 1.1.0、Node.js 24.19.0、kimi-k3、实际 thinking=high、单回复最多 8192 tokens、单例主阶段 720 秒，串行交错运行。Cairn 预留 90 秒收尾。两组都追加相同 `checks.json` 契约；Cairn 还承担提交清单和交接记录的流程要求，宿主在线执行组合验收，Pi 结束后执行同一检查。

独立复算器只读运行前冻结的原 CSV，核验精确序列名、2–10 项不同序列、证据关联、半开窗口及 mean/min/max/差分 rate，误差容限为 1% 或 1e-6。它不执行 Agent 提交的复算脚本，不读隐藏根因标签，也不从指标名称推断采集语义。隐藏标签仅用于主阶段结束后的评分。`method=replay` 和 scope 随回执保存。

生产构建与 **225/225** 自动化测试通过，记录在 [implementation-tests.log](runs/2026-10-17-aiops2022-round3c/implementation-tests.log)。正式运行的冻结实现、输入、验证器、评分与产物完整性等 **537/537** 记录检查通过，详见 [summary.json](runs/2026-10-17-aiops2022-round3c/summary.json)；这不是 537 项内容正确性检查。主阶段路径扫描检查 63 个显式路径及 114 条 bash 请求文本，未标出可疑项，仍不能证明动态路径隔离。

**未启用 OS 沙盒。** Pi 恢复第一条命令列出了工作区父目录并尝试不存在的 `../TASK.md`，越过提示约定的工作区边界；返回中包含 `initial.grade.json` 等文件名，没有观察到读取隐藏评分内容。后续显式 read 是本工作区 TASK.md、answer.json、checks.json。见 [recovery-scope-audit.json](runs/2026-10-17-aiops2022-round3c/recovery-scope-audit.json)。父目录中的评分文件在权限上可读，这是评测隔离的限制；恢复不用于提升主阶段准确率，也不能作为严格防泄漏证据。

每条件每例仅一次、无固定 seed，且本轮比历史轮次多了数值契约和恢复协议，耗时、完成数和类别变化都是描述性观察，不能隔离两项功能的因果贡献或推导普遍收益。公开数据可能存在于训练语料，当前无法排除。

## 后续优先级

保留现有五工具、SQLite 黑板、Finding 历史与宿主原生执行，不引入额外常驻模型。优先收紧与领域无关的两个边界：完成前明确核对“对象层级／替代解释／未覆盖反证”，以及让缺发现、缺提交物时的 finish 修正路径更直接。领域复算器仍作为可替换宿主组件，避免把 RCA 规则塞进通用核心。中途交接应另做预先固定中断点的重复恢复实验，再判断它是否减少重做与成本。
