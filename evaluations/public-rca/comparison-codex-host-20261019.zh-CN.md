# Codex + GPT-6.1-Sol 极高 × Cairn 补测（2026-10-19）

本轮沿用上一轮三道公开排障题，每题一个新会话、一次正式执行，共3次，模型固定 `gpt-6.1-sol`、推理级别 `xhigh`，不设置任务时长、调用次数或 token 预算。三题并行提交，平台错开派发，三个实际模型执行区间有 19 秒共同重叠。复用原生 Codex app-server 执行，接入 Cairn 六工具，未启动独立 Scheduler。

**结果：严格正确2/3，报告交付3/3，Cairn闭环3/3，错误完成1/3。** 本轮未超过 Pi + DeepSeek 的诊断命中率；Sol 的平均主会话 tokens 最少，平均执行耗时最长。

## 失分和重试原因

1. **I/O 与伴随内存压力的首因排序仍不稳定。** `new-01` 首选 `shippingservice / service / memory`，冻结标签为同服务的 `disk_io`。模型已观察到节点I/O、等待与服务延迟变化，报告仍保留“node-5 I/O 可能先行”的替代解释，但优先选择了“容器近内存限制、failcnt增长”的内存压力。证据并未从上下文消失；这是已保留证据的归因优先级问题。现有交付验收没有独立的真实根因答案，因此没有把这次错误归因当作未交付。
2. **11次工具校验或状态错误均自行恢复，保留全部耗时和 tokens。** 三次把 finding 的 `text` 写成 `claim/statement`；三次把 checkpoint 的 `artifacts` 写为路径字符串数组；三次证据查询 `limit` 超过200；一次使用了当前任务不可用的快照编号；一次先读状态而尚未创建目标。最终每题均只创建一个正式目标、一次成功调用 `cairn_finish`，没有靠人工改答案或放宽验收完成。
3. **平台额外上下文与工具发现有开销。** 每题启动时都做了两次内置资源发现；本轮不是严格只调用六工具与业务工具的零探索路径。实际配置只连接 `cairn` 和 `application`，完整原生工具记录没有 Shell、其他模型、其他 Issue 列表或全局服务调用。原始 `strictToolsOnly` 字段保留为 false，额外只读资源发现单列审计，没有事后改成通过。
4. **平台网络与日志上报问题独立存在。** Multica 的 Go/TLS 链路出现超时与重复派发等待，并漏传部分工具事件。三题完整原生记录分别有 68, 54, 61 次MCP调用，平台保存的事件分别只有 59, 37, 61 次。若仅看平台UI，会误以为部分工具未调用；用量与调用核对采用精确原生会话，证据和交付另用独立账本验证。回读CLI按自身诊断建议使用 `GODEBUG=tlsmlkem=0`；未据此修改已经运行的模型或重写其输出。

后续优先改进的是通用契约可发现性（完整字段与示例、错误后的最小重试）、事实成立与首因排序的分层审查，以及平台原生事件同步。不能把这次标签写成“优先选I/O”的案例规则；本轮也没有为答错题选择性重跑。

## 一致性和统计边界

- 与上一轮相同的 Cairn 4.9.0 核心、只读查询实现、777字符系统提示词及原始材料，已核对哈希；每题57份CSV，共171份。Issue正文只描述业务任务与验收，不包含 Cairn 指令；原始材料未修改。新会话、证据账本、产物和回执均按 Issue/原生线程隔离。
- 目标工具MCP使用上一轮冻结CLI；Codex hook包采用当前4.9.0构建。整包差异为包说明、UI文字、Claude专用schema兼容与doctor输出；本轮实际使用的hook、宿主选项、用量、engine、store及tools模块已逐一核对一致。
- Codex使用原生MCP请求元数据的 `threadId` 绑定冻结Cairn CLI；不从最近会话推断身份，也不由模型编造身份。6个目标工具保持原实现，3个目标均为 `curated`、预算为空、3个必需文件、独立交付验收器。
- 正式开始前发现 Multica 0.6.3 在每任务私有配置中保留了无关全局MCP。SHEN-25/26/27三次联调已取消并保留原因，正式成绩使用隔离后的新Issue SHEN-28/29/30；同一题没有因答错而再跑。另有无领域答案的合成接入探针。联调和探针不计正式均值，因此表格不是整次操作的账单。
- tokens来自完整原生主线程累计数字，并与按唯一 `response_id` 去重的响应账本逐项对账。三题合计 **4,854,904 tokens**；输入已包含缓存读取，输出已包含推理，不重复相加。原生账本已归档并核对SHA-256；未把私有认证文件放进报告。

- 本轮代码改动限于评测传输、完整账本统计和审计支持，没有改写Cairn推理或特定题目策略。全量回归 **478/478通过**。
