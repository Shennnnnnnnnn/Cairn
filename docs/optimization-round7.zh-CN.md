# 第七轮：Codex 实测与当前事实的有效性

本轮按同一较难公开案例 `case-03` 比较原生 Codex CLI、冻结上一版 Cairn、冻结本轮修改前 Cairn，再以修改后的 Cairn 补跑一个新会话。模型为 `gpt-6.1-sol`，推理等级 `xhigh`，不设置评测时长、调用次数或 token 预算。前三组并行。源程序、输入、提示词、数值验收器和 CLI 配置在启动前冻结；第四组沿用同一测试条件。

这是一个已多次使用的案例，每组一次运行。跨 Pi/Codex 的历史比较同时改变了模型、宿主及其默认指令；不能据此声称隔离了纯模型效应，也不能把一次命中率当作稳定成功率。用量按各宿主原始统计另列，不能用订阅 CLI 的 token 数推算实付 API 金额。

## 优先落地点

| 问题 | 已有证据 | 本轮处理 | 边界 |
| --- | --- | --- | --- |
| Codex MCP 未收到宿主配置，完成验收静默退化 | 首批 Codex 实测中，三组 MCP 任务均写入 Git 仓库默认 DB，且 completionVerifier/requirements 为空；hooks 的独立 DB 则无任务 | 安装器用 env_vars 显式转发 CAIRN 数据库、验收与时限配置的变量名；评测还显式传 --db，并检查实际任务和宿主验收身份 | 不持久化环境变量值或凭据；首批完整保留并作废，修正后四组全部新跑，不以独立事后复算冒充运行中的宿主验收 |
| 完成后的旧行动仍被当作当前行动 | 上轮四个当前版执行者的自动交接继承旧 checkpoint.next；context 的 agenda 仍要求 finish | 终态的当前投影显示已完成与复用边界；保留历史 checkpoint；重开任务立即保存新代次交接；有界恢复优先保留当前 host handoff | 不把完成改称正确，不清空历史，不改变工作分支待 owner 审查的含义 |
| 文件更新，引用它的旧事实仍有效 | 上轮 GLM 的事实记录称 8 项检查，最终产物实际为 6 项；字符串引用没有内容版本 | 仅对显式引用且已声明为产物的本地文件记录宿主计算的内容摘要；内容变化时提示重审，阻止过期事实充当完成依据；显式重新提交该事实才重新绑定 | 不自动改写事实或判定语义真伪，不扫描任意引用，不增加模型侧字段，不追溯伪造旧记录的校验 |
| 数值验收的排重规则说明不够明确 | 同一原始序列重复做不同窗口或运算仍被已有验收器排重，旧契约表述不够具体 | 新增 v2 契约说明唯一键为规范化 `(file, entity, metric)`，补重复来源及路径别名用例；本轮四组统一使用 v2 | 不修改旧契约、旧验收结果或冻结的验收算法 |

## 保留的设计

仍使用五个公开工具、显式的小事实增量、外部命令完成实际工作；`finish` 仍只有 `outcome/summary`。产物验收、执行完成和独立结论审查保持各自含义。新增文件元数据由宿主计算；模型不能自报文件哈希来获得验收。SQLite 保留完整事实历史和交接记录，Markdown 文件为便利投影。多会话仍使用原生 session 标识、owner epoch 和显式 takeover，不增加会话调度器。

## 已落地与回归

核心修改 `src/core/artifacts.ts`、`engine.ts`、`handoff.ts`、`types.ts`、`src/tools.ts` 及 Codex 安装配置 `src/install.ts`，并更新既有 skill。没有新增运行时依赖、工具、后台调度或领域根因规则。

- `referenceArtifacts` 由宿主计算；`referenceState` 是有界投影，不写入 proof。旧记录不追溯补字段，正文声明与历史覆盖链接保留。
- criterion 和当前报告引用的过期事实阻止完成，验收前后也复查；独立审查的 current 状态同步失效。候选报告校验检查候选自身的引用。
- 同 key 重新确认文件版本产生一次修订，相同重试保持幂等；旧 SDK 的匿名 finding、同批前向依赖别名也沿用原节点。SDK 伪造的宿主文件元数据会被忽略。
- 当前完成投影停用旧 next，旧数据库也生效；重开保存新代次 handoff，手写交接仍按相关性优先，最多三条内保留 host/state，裁剪时不挤掉它。历史数据库状态、旧正文和文件不因读取被修改。
- 包含 Codex 配置转发的完整构建与 **262/262** 测试通过。新增回归包含相同大小文件替换、删除、产物重拍不刷新事实、异步验收中的修改、旧记录、匿名别名、候选报告、完成幂等、旧完成交接、重开、worker 与挂起接管。单纯的重载测试不等于真实模型超时恢复成功率。

冻结修改前、修改后各 85 个运行相关文件。相对于本轮修改前归档的增量见本地评测目录 `implementation.delta.patch`；它不会混入此前尚未提交的优化差异。

Codex 的 stdio MCP 需通过 env/env_vars 显式设置或转发环境配置，见 [官方 MCP 文档](https://developers.openai.com/codex/mcp)。原先在 `/tmp` 且没有 Git 祖先的接入探针未暴露数据库回落，也未验证宿主 verifier，本轮改为仓库内带独立数据库及合成产物验收的探针。首批额外消耗 3,372,021 记录 tokens，保留 `runs/2026-10-17-codex-sol-xhigh-round7/invalidated.json` 和 `misrouted-tasks.json`；不计入正式对照。正式结果使用 `round7b`，不能沿用首批的完成或成本结论。

## 最终实测

纠正后的四个全新会话均自然结束；前三组并行，空出一个执行位后启动修改版，最大并发三组。四份完整公开报告审阅冻结后再统一运行隐藏评分。完成、原始 CSV 独立数值复算、首选对象＋资源类别均为 **4/4**，错误完成 **0/4**；三个 Cairn 任务还通过各自冻结引擎的当前报告和验收 proof 检查。冻结与记录审计 **852/852** 通过。

| 配置 | 耗时 | 记录总 tokens | 输出 tokens |
| --- | ---: | ---: | ---: |
| 原生 Codex | 316.64 秒 | 472,280 | 16,778 |
| 冻结上一版 Cairn | 477.79 秒 | 1,367,896 | 23,662 |
| 本轮修改前 Cairn | 410.54 秒 | 1,001,652 | 24,109 |
| 本轮修改后 Cairn | 395.71 秒 | 681,455 | 21,456 |

修改后相对修改前耗时少 **3.6%**、记录 tokens 少 **32.0%**，实际绑定文件版本的事实为 **4 条**，checkpoint 调用 6→5，finish 均为一次。修改版仍出现一次 findings 对象字符串化及一次自写验证脚本失败后修复，接口问题没有消失。原生 Codex 的耗时和用量仍最低；一次新采样的差值不能直接算作代码收益，本题没有观察到准确率提升。没有真实超时／上下文恢复，恢复为 N/A。

正式四次合计 3,523,283 tokens；作废批次及三个接入探针另计 3,614,407 tokens，不隐藏开发开销。记录 tokens 含缓存输入，不等于订阅金额。完整模型比较、方法限制、审阅和运行目录见 [最终实测报告](../evaluations/public-rca/comparison-codex-round7.zh-CN.md)。本轮没有新做 UI 浏览器验证。
