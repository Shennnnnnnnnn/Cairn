# 第八轮：范围审视、checkpoint兼容与增量收据

本轮针对上一轮封存记录中的三种问题修改通用协议。没有资源族、案例名称或层级优先规则，没有新增模型工作者或运行依赖，仍然五个工具、curated默认、宿主执行。

## 实现

`src/tools.ts`在模型checkpoint的严格校验前做单层传输规范化：finding数组中合法JSON对象字符串解码后仍须满足原schema；空白可选next按省略处理，保留原来的下一步。普通文字、数组、null、缺字段、非法状态和伪造宿主引用快照都不会变成事实。公开schema继续要求对象；finish仍只允许outcome/短summary。该兼容覆盖实际MCP传输，并保持重试幂等。

模型checkpoint收据返回新增/修订项和选中的失效引用，保留覆盖缺口、验证/修复反馈、问题与下一步；不再复制整份旧finding索引、刚提交过的事实文本和多个历史交接路径。模型finish沿用紧凑确认。SDK收据、显式read、数据库完整事实/历史与分支租约返回保持。完整黑板和交接按需读取，压缩不会刷新旧事实或解除文件版本约束。

`src/core/engine.ts`和skill明确要求比较原始目标与结论的主体/范围，区分观测和解释，保留最强替代解释及区别性证据；共享效果、汇聚点或同时变化本身不能定位起因。没有自动提升/降低结论层级的规则，也不把这一模型自审称为独立正确性验证。长探索提醒只携带简短缺口/开放项和新增hint，重复说明移到skill/工具协议一次表达。

原项目`dispatcher/prompts/default/reason.md`先审视事实是否满足Goal，再纠偏意图；`explore.md`要求仅写最新增量事实并将长材料放文件。本轮保留这两个原则，将宿主模型作为探索者，不恢复独立reason/explore模型池。原项目材料只作为设计参考，不作为用户授权或新约束。
