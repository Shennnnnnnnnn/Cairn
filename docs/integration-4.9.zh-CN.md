# 4.9 主线整合说明

本次将 `codex/general-harness-optimization`（`bc391cd`）与已有主线（`46a798f`，4.8.0）整合，代码与当前文档统一为 4.9.0。

## 保留的能力

| 能力 | 整合后的行为 |
| --- | --- |
| 通用六工具 | 主线 cairn_update 即时状态保留；模型 finish 收窄为 outcome/summary，SDK 旧输入保持兼容 |
| 完整图与探索 | 保留不可变快照、分页、增量、来源版本、派生结论失效、署名反馈及显式重开 |
| 多会话 | 宿主语义分支和原生生命周期保留；显式委派工作项可由独立会话租约认领，过期或 owner 代次变化隔离旧写入 |
| 调度 | 可选 Bootstrap/Reason/Explore 复用宿主 CLI；默认 auto 路由、fresh-full，支持显式启动和增量复用策略 |
| 复核门槛 | 调度黑板携带语义分支、原生运行及 globalReview 快照；负责人显式确认，worker 不可确认，新证据继续待审 |
| 验收与交接 | 本地文件 SHA-256、引用版本、宿主验证器、独立 assessment、自动 SQLite 交接与文件投影分别保留 |
| 看板 | 自然时间回放、主/子 Agent 分区、即时更新、token/调用/时间统计，与任务/产物/结论独立状态共存 |
| 通用边界 | 延续主线移除比赛流程的决定，不恢复 emergency profile、delivery/confirm 或固定排障报告字段 |

语义 Branch 记录问题、来源和审阅过程；progress 的 lease 控制 worker 写入权。两者共用任务、图和完成门槛，租约合并不自动接受结论。共享 source `from` 只表达声明的共同前提，不证明因果。

自动调度的原生阶段返回数字按独立 invocation ID 去重。未返回的指标不估算，统计不产生证据、不授予完成覆盖。原生 hooks 和 CLI 阶段报告的统计边界应按来源阅读。

## 文档和历史边界

当前指南统一说明六工具、窄 finish、复核与调度默认值；[导航](README.zh-CN.md) 区分使用指南和历史实验。各轮实验报告保留冻结代码、计分及原始结论，不把旧报告包装为 4.9 的模型实测。移除的比赛 fixture 不再作为当前文档入口。

本次完整回归 **450/450** 通过（包含类型检查和构建），另有实际 Pi CLI 的隔离 loopback 夹具。详细结果记录在[验证日志](verification.md)。没有额外运行真实模型对比；当前版本的准确率和成本不能由历史测试直接推断。
