# 阶段输出与协调上下文优化

本轮保持五工具 harness 为默认入口，可选 Scheduler 继续复用 Pi／Codex 原生执行；没有新增模型服务、领域流程、案例判断或依赖。自动闭环保留 Bootstrap 直接尝试、Reason 审核黑板、独立 Explore 提案及 owner 授予覆盖的关系。

## 修改

- **共享阶段契约**：从同一 schema 生成紧凑提示并校验，明确字段、长度、数组上限与依据要求。允许完整 JSON 的单层代码围栏，不从解释文字中提取或猜测候选。owner 的事实、Intent、产物和交接通过同一次 checkpoint 提交。
- **同会话输出纠错**：结构或参数不合格时，只反馈有界字段问题，沿用原生会话纠正最终输出。保留最初的黑板指纹，错误日志不作为新知识；新提示仍使旧 Reason 失效。相同错误签名再现即保存缺口并停止，没有固定调用或 token 预算。
- **减少重复上下文**：单次运行内复用已退出的协调会话，发送变化记录、删除 ID 及完整快照定位；目标、约束和完成条件始终保留。游标是实际派发的输入，接管和重启后重建完整输入。Explore 保持独立会话与 proposed／零覆盖权限。
- **产物修复与恢复边界**：本阶段写文件不再被误判为外部黑板变化；重复完成判断包含实际文件版本。旧 finding 的引用版本仍需显式复核重存。恢复旧 Reason 前确认原进程退出，无法确认则保留在途记录并停止。

Pi 输出纠错通过最终工具排除配置禁用全部工具。Codex 使用公开动作审计，覆盖 started／updated／completed 并按 ID 去重；这是事后拒绝机制，不能阻止已经执行的动作。两者均拒绝带动作或动作数缺测的纠错候选，不以自动填充依据换取完成率。

## 验证与测量

新增非排障回归覆盖超长引用同会话纠正、交替错误停止、纠错中新增提示、无效 Intent 原子性、未知或非零动作拒绝、完整快照／增量一致性、快照目录不安全时退回完整输入、取消、恢复隔离及产物版本约束。零模型原生接入夹具和完整检查另有记录。

本轮正式比较为 DeepSeek／GLM／Sol、原三题每题三次、原生宿主与可选 Scheduler+Cairn 两组，共 54 次，无评测预算。所有阶段、纠错和失败成本都计入。普通协调会话复用、参数纠错与故障 Conclude 分开统计；身份匹配不代表成功恢复。三题属于反复使用的开发集，结果不证明任意任务的性能，也不构成单项修改的严格因果消融。
