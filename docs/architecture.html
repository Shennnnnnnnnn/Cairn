概述

什么是 Cairn

Cairn 是一个通用问题求解引擎。它将任何具有「明确起点 + 明确目标 + 未知路径」 结构的问题统一建模为状态空间搜索，无需预定义角色、工作流或领域知识。 AI 渗透测试是第一个经过验证的应用领域：在腾讯云 Hackathon 智能渗透测试大赛中， Cairn 以 54/54 全题通过成为全场唯一 AK 团队（最终排名第 3）。

🎯

问题结构

任何满足 Origin → ? → Goal 结构的问题都可用 Cairn 求解。渗透测试、CTF、漏洞研究、数学证明——形状相同，引擎通用。

🧠

无角色设计

Agent 没有固定角色。任务在运行时从当前图状态生成，不依赖预定义的 Job Description。Agent 只接收 Prompt，返回结构化输出。

🐜

信息素协调

Agent 之间不直接通信。所有协调通过共享黑板（Stigmergy）完成，消除信息孤岛。

核心概念

核心概念 — 黑板架构

整个系统由三个原语驱动：

事实 Fact

写入黑板的客观、已验证发现。每个 Fact 有全局唯一 ID。图中有两个特殊 Fact：origin（已知条件）和 goal（目标，仅在项目完成时由完成意图指向）。

意图 Intent

声明的探索方向，尚未执行。Intent 具有 from（源 Fact 列表）和 to（目标 Fact，执行后填写）字段，串联 Fact 形成有向图。

提示 Hint

人类在任意时间注入的判断或提示。Agent 在下次读取黑板时自动吸收所有 Hint，无需中断正在运行的任务。

事实-意图图 — 从起点到目标的有向图生长过程
系统架构

系统架构总览

系统架构总览图

服务端（Cairn Server）

纯状态持久化层，不参与决策。维护 Fact-Intent 图的一致性，通过 REST API 暴露读写接口。并发写入通过 SQLite 事务保护。内置 Web UI，可实时查看图状态、注入 Hint、控制项目生命周期。

调度器（Dispatcher）

系统的决策中枢。每隔 interval 秒轮询 Server 状态，决定派发什么任务给哪个 Worker，管理容器生命周期，写入执行结果。Worker 之间的协调完全通过 Server 上的共享状态实现。

任务类型

三种任务类型

Bootstrap 引导

直接求解尝试

触发：项目初始
输出：事实 + 完成

在项目刚创建时（只有 origin 和 goal 两个事实），尝试直接一次性解决问题。Prompt 只包含 origin、goal 和 hints。成功时写入一个事实并调用 complete 将项目标记为已完成。失败或超时时触发 Conclude Fallback。

默认超时：300s + conclude 90s
Reason 推理

图状态推理

触发：图状态变化
输出：完成 / 新意图

读取完整的事实-意图图（YAML 格式），判断：目标是否已达成？应探索哪些新方向？输出为 complete、新意图列表（最多 max_intents 个），或 noop。通过 Reason Checkpoint 机制避免重复推理。

默认超时：300s · max_intents: 2
Explore 探索

意图执行

触发：有未认领意图
输出：一个事实

认领一个开放的意图，在工具环境中实际执行探索（网络扫描、漏洞利用、代码分析等），将发现写回为一个新的事实。支持并发（多个 Explore 任务同时运行）。Dispatcher 优先选择最新创建的意图。

默认超时：300s + conclude 90s

主循环流程（DispatcherLoop.run）

while True:
    1. _validate_server_settings()      # 验证 Server 超时配置与 interval 的一致性
    2. _reap_futures()                  # 收割已完成任务，处理 success/failed/unhealthy/rejected
    3. _reap_cleanup_futures()          # 收割容器清理任务
    4. summaries = client.list_projects()
    5. _initialize_reason_checkpoints() # 为有开放意图的项目初始化检查点
    6. _refresh_runtime_projects()      # 同步活跃项目集合
    7. _cancel_inactive_tasks()         # 对停止/完成项目的运行中任务发出取消信号
    8. _queue_container_cleanups()      # 为停止/完成项目排队容器清理
    9. _dispatch_available(summaries)   # 核心：为每个活跃项目派发任务
    sleep(interval)

轮转调度（Round-Robin）

Dispatcher 使用 project_cursor 实现跨项目的公平轮转调度。每次调度循环，项目列表按字典序排序后偏移 cursor，确保不同项目都有机会获得资源，防止某个项目长期占用所有 Worker 槽位。

Worker 后端

Worker 后端适配器

每种 Worker 通过实现 WorkerDriver 接口接入。接口定义了四个方法：build_healthcheck、build_execute、build_conclude、extract_response_text。

Worker类型支持任务SessionConclude 回退认证
claudecode SeedSessionDriver 推理 ✓ --session-id ✓ -r <session> 本地 claude CLI
codex RegexSessionDriver 引导 探索 ✓ 正则提取 ✓ resume <id> 本地 codex CLI
gemini WorkerDriver 探索 部分（stderr 提取） ✗ 不支持 GEMINI_API_KEY / gemini auth
pi WorkerDriver 全部 依配置 依配置 PI_API_KEY 等环境变量
mock WorkerDriver 全部 N/A N/A 无（测试用）

Session 机制

对于需要 Conclude Fallback 的任务（execute 超时或输出异常），Dispatcher 需要在同一个对话上下文中继续追问。

  • SeedSessionDriver（Claude Code）：execute 前预生成 session UUID，用 -r 恢复
  • RegexSessionDriver（Codex）：从 stdout/stderr 用正则提取 session ID
  • Gemini：从 stderr 提取 Conversation ID，但不支持 conclude

心跳机制

HeartbeatLease 在后台线程中周期性地调用 Server 的心跳 API，告知 Server 该意图仍在被 Worker 处理中。若 Worker 崩溃，Server 会在 intent_timeout 后自动释放该意图，使其可被其他 Worker 重新认领。

Conclude 回退机制

当 execute 阶段超时或输出无法解析时，如果 Worker 支持 session 恢复，Dispatcher 会追加一个 conclude 提示词，要求 AI 从已执行的操作中提炼出部分发现写入事实。保证即使任务不完整，也能留下可用的探索记录。

数据库

数据库 Schema

表名主键关键字段说明
settings rowid=1 intent_timeout, reason_timeout 全局超时配置（秒）。Dispatcher 启动时验证与 interval 的一致性。
project_directories id name UNIQUE, local_path 项目目录，local_path 挂载为 Worker 容器的工作目录。
projects id status, reason_worker, scheduled_start_at reason_worker 实现乐观锁（同一时刻只允许一个推理任务）。scheduled_start_at 支持定时启动。
facts (id, project_id) description 不可变记录。origin 和 goal 为系统保留 ID。
intents (id, project_id) to_fact_id, worker, concluded_at worker IS NULL = 未认领；to_fact_id IS NULL = 开放；concluded_at IS NOT NULL = 已完成。last_heartbeat_at 用于超时检测。
intent_sources (intent_id, project_id, fact_id) fact_id 意图的来源事实关联表，支持一个意图由多个事实触发。
hints (id, project_id) content, creator 人类注入的提示，只增不改不删。
counters name value 自增计数器，用于生成 ID（projects, facts, intents, hints 各一个）。
配置参考

配置参考（dispatch.yaml）

server: "http://127.0.0.1:8000"  # Cairn Server 地址

common_env: {}               # 注入所有 Worker 的公共环境变量

runtime:
  interval: 3               # 调度循环间隔（秒）
  max_workers: 8            # 全局 Worker 并发上限
  max_running_projects: 3   # 同时活跃项目数上限
  max_project_workers: 4    # 单项目 Worker 并发上限
  healthcheck_timeout: 60   # Worker 健康检查超时（秒）
  prompt_group: "zh"        # 提示词语言组（zh / default）

tasks:
  bootstrap:
    timeout: 300            # 执行阶段超时
    conclude_timeout: 90    # Conclude 回退超时
  reason:
    timeout: 300
    max_intents: 2          # 每次推理最多创建的意图数
  explore:
    timeout: 300
    conclude_timeout: 90

container:
  runner: "local"           # "docker" 或 "local"（直接在宿主执行）
  image: "cairn-worker-local:latest"
  network_mode: "host"
  completed_action: "stop"  # "stop" 保留容器 / "remove" 清理容器
  # cap_add: [NET_RAW, NET_ADMIN]
  # volumes: ["host:container:ro"]

workers:
  - name: "claudecode"
    type: "claudecode"
    task_types: [reason]
    max_running: 1
    priority: 0             # 数值越小优先级越高

  - name: "codex"
    type: "codex"
    task_types: [bootstrap, explore]
    max_running: 2
    priority: 0

  - name: "gemini"
    type: "gemini"
    task_types: [explore]
    max_running: 2
    priority: 1             # 次级选择，codex 满载时使用
