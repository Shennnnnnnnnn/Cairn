# 第九轮：编码兼容与因果比较

本轮保留五工具、宿主原生执行、默认 curated、增量事实和版本化交接。不增加模型工作者、资源分类器或强制报告字段。

## 对象数组入口

`cairn_checkpoint` 的 findings、progress、artifacts、handoffs 复用一个有界规范化函数：数组元素如果是至多32000字符的单层 JSON 对象字符串，先解码，再经过原来的严格 schema 与引擎校验。正常对象不变；不解析整列字符串、嵌套编码、自然语言或任意自由文本，不推断 key/status/covers/path。发布给模型的 schema 仍要求对象。调用方输入不修改，整次调用拒绝时不保存合法子集。

除 findings 外，本轮补齐其余三类对象数组；保留数量/字段上限、产物哈希由宿主生成、@host/交接保留键、显式文件版本绑定和分支租约门禁。SDK 历史接口不改变，finish 仍只接受 outcome 和短 summary。

Pi 1.1.0 会先验证工具参数、后执行扩展。其文档接口 `prepareArguments` 现在调用同一规范化函数，在宿主验证前处理编码；execute 内依然严格验证。MCP 入口继续使用同一模型协议，不扩大公开 schema。

## 起因与伴随压力

增加通用比较步骤：先在同一对象上比较不同机制，避免把“换层级”和“换机制”绑成一次选择；一个层级上的反证不能自动排除同一对象上的另一个机制。观察到的压力可能是起因、中介或后果。保存最强备选解释及有区分力的预测，利用可用的先后关系、方向或受控改变；粗时间采样和共现不能证明因果方向，证据不足时保留不确定性。

这通过现有 finding status/from、questions/next 和轻量探索提示生效。不会自动更改事实状态、生成领域答案、要求额外审查回合或给任何机制/层级默认优先权。它是探索指引，不是独立正确性判定器。

固定无领域请求的字节测量：首批checkpoint为2119字节、修订1347、幂等重试1191，与round8一致；工具目录+61字节，skill+260，初始/恢复投影+107，短提醒+51。六个事实、反证状态、问题和下一步均保留。这是固定请求的字节比较，不是模型token或账单节省。

## 验证

完整测试272/272通过，新增5个定向测试覆盖四类对象数组混合编码、不可变与幂等、严格/原子拒绝、版本绑定、Pi 验证前准备和未决解释恢复；真实 MCP 用例覆盖 artifacts/handoffs/progress 的传输。上轮三份真实编码拒绝载荷在本机Pi校验器只读重放：原始均拒绝、统一准备后3/3通过，调用方不变；该检查只验证传输形态，不跳过后续文件/引用/所有权语义门禁。

同模型真实 Pi 接入探针：global:deepseek-v4.1-flash / high，31528 recorded tokens，0工具错误，独立DB/原生owner/宿主验收proof通过。探针成本不并入正式矩阵。

18次真实对照已全部结束（最多3并发、无评测预算），逐份报告封存后统一隐藏评分。两组联合命中均9/9；原生/Cairn完成及有效交付8/9、9/9；错误完成均0。原生少一次交付源于连接错误，不能全部归因于框架。数值复算18/18、格式契约17/18；Cairn完成proof9/9有效。冻结/记录审计581/581、独立原生记录126/126、额外统计核对36/36通过，19份私有配置副本均删除。

Cairn共20次checkpoint和9次finish，无Cairn工具失败；正式调用均为对象，没有触发字符串兼容分支，不能据此单独证明该分支收益。全尝试recorded tokens为原生33,899,676、Cairn20,578,755（少39.3%）；每次有效交付记录tokens少46.0%，非缓存输入+输出少29.1%；CLI累计耗时少24.6%。API/流错误使两组用量均只能作为下界，实际金额未知。
