## 与原版及 OpenRig 的关系

原版 `dispatcher/prompts/default/explore.md` 要求只返回最新增量事实，较长数据另存文件；`dispatcher/contracts.py` 将 explore 的事实结果与 reason 的 complete／intents 分开；`server/routers/projects.py:257` 的 complete 只消费已有 fact ID 并形成到 goal 的关系。本轮沿用这项分工：模型 checkpoint 保存新知识，finish 消费已存状态，详细探索可链接文件。原版的图连接和完成标记本身也没有独立证明根因正确，因此仍保留产物验收与结论审查两种范围。

与原版相比，宿主原生会话仍负责执行、权限、模型和终止；没有搬回 reason／explore worker pool 或服务端调度循环。原有五工具、captured E#、emergency 真实交付／确认及 owner fencing 继续生效。旧 SDK 输入保留兼容，MCP、Pi 和自定义模型循环使用同一 `invokeModel` 校验。

OpenRig 的借鉴点是来源身份、候选版本、执行代次和交接阶段分离。自动交接在接管前保存旧 owner，worker 快照带分支及真实作者；生成报告不能替代对方 ACK。没有新增进程管理、跨机会话服务或消息 outbox。详见 [多会话对照](multi-session-reference.zh-CN.md)。

## 同模型实测结果

[完整第五轮比较](../evaluations/public-rca/comparison-round5.zh-CN.md)保留十二个主阶段、十一段恢复和 23 份独立审阅，冻结检查 923/923。三组主阶段均完成 0/4；新版仅 CPU 例保存了有效但未完整交付的答案。含必要恢复后，旧版正确交付 4/4，新版与原生 Pi 为 3/4；错误交付分别为 0/4、0/3、0/3，不能以没有完成而声称错误率改善。没有真实时间超时，主要是累计输出预算停止；Pi 网络例另有单次 length 退出且未交付。

新版三个成功续接的 finish 参数最多 478 字节；模型侧不再提交大段 findings/from。主阶段含事实 checkpoint 新版 3/4、同模型旧版 4/4，双方都没有成功的仅摘要 checkpoint。新版自动交接 7 份，其中 3 份含事实；网络例只有空的创建快照，模型未保存事实，恢复也失败。基础副本恢复新旧合计 8/8，完整有事实交接定位为新版 3/4、旧版 0/4；后者不是模型恢复率。

含恢复观察耗时旧版 1091.69 秒、新版 1134.98 秒；记录 tokens 至少 5535666／5579487，价格未知。不能从工具 schema 缩小推导总体成本下降。新模型下实际提前耗尽的是输出预算，基于时间期限的 90 秒预留未覆盖它；当前可选工具也不能强迫一直使用原生工具的模型交事实。下一优先级是通用宿主剩余输出／length 信号与有界保存阶段，而非继续增加完成字段或领域硬编码。

复盘 UI 已更新为 33 个任务，源状态 33/33 哈希未变；ego-browser 核验了成功续接的验收与结论审查、自动交接定位、未完成任务的保守过期审查和空事实网络例。测试浏览器空间已关闭，8012 服务保留。[看板入口](public-rca-ui.zh-CN.md)。
