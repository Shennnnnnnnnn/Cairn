# 第四轮：产物验收与分层交接

日期：2026-10-17。目标：把已选定的两项机制落到现有宿主协议中，保留通用、轻量的结构，再用既有四个公开排障案例验证实际效果。

## 实现与原版思想

| 本轮改变 | 承接的思想 | 通用核心与宿主的边界 |
| --- | --- | --- |
| 显式提交文件，宿主计算 SHA-256 和字节数；验收绑定提交内容及 owner epoch | 完成应由可验证产物支持，外部失败反馈继续驱动探索 | 核心负责提交完整性；实际复现、领域语义和进程隔离由宿主验证器负责 |
| 独立保存带 key 的交接记录，关联已有 Finding／work | 黑板保存增量状态，具体探索留在文件及可追溯会话中 | 不复制原始会话，不增加后台总结模型；文件引用不自动成为证明 |
| 根据当前工作或 focus 优先恢复相关前提与交接 | 从已有事实和开放探索继续，而非只看最近消息 | 视图保持预算，省略项可分页展开；保留共同前提与历史 |
| `serve / submit / status / graph / hint` CLI | 保留按任务 ID 操作共享状态的便利性 | 使用现有 SQLite 与看板，模型执行交给 Pi／Claude Code／Codex 等宿主 |

依旧是五个公共 Agent 工具。没有增加常驻调度器、模型 Worker 或固定领域角色。原有 Finding 历史、共同前提、租约和 owner fencing、反馈重开保持有效。

## 具体行为

- 最多显式提交 16 个普通文件、总计 64 MiB。文件在验收期间或通过后发生变化，原回执不能继续支持完成；换 owner epoch 也必须重新验收。
- 宿主可声明必需提交物，并以固定命令返回 `{ok, issues, method, scope}`。方法支持 replay／inspection／contract，未声明的方式显示 unspecified。核心不把验收通过解释为任意领域的正确性证明。
- 交接层次为图摘要 → 探索报告及材料 → 原会话定位。交接不授予 criterion 覆盖，同 key 内容变化追加记录，精确重试去重。
- `cairn_read(view="context", focus="c1")` 保留相关旧前提；`view="handoffs"` 根据 key／ID 展开交接详情。原始内容仍由宿主保存。
- CLI 提交任务后返回 host-managed 回执；由宿主 `cairn_resume(..., takeover=true)` 接手。`serve` 是现有本地 UI 的别名；独立 review 阶段不属于本轮。

字段、示例和限制见 [产物验收与分层交接](artifacts-handoffs.zh-CN.md)。

## 回归证据

生产构建与全部 225 项测试通过。新增覆盖包括提交物快照、必需文件、验证器修改文件、通过后文件变化、换会话旧验收失效、交接追溯、旧依赖恢复、worker 写入限制、CLI 工作流及独立数值复算。

数值复算回归使用手工可算的 mean／rate、伪造数值、差分遇到回退、实际磁盘指标名称，以及不在冻结原始证据清单中的伪造 CSV。它使用独立实现读取原 CSV，不执行 Agent 提交的脚本。

## 公开案例复验协议

沿用 case-01 至 case-04、模型 Kimi K3、high thinking、串行交错顺序、每例 720 秒主预算和输出预算。两组同时追加 `checks.json` 数值复现文件要求；Cairn 宿主组合结构检查与独立 CSV 数值复算。隐藏故障标签只用于进程结束后的评分，不参与在线验收。

自然超时或输出预算停止后，以全新会话、同一工作区追加 180 秒。恢复成绩、耗时与 token 单列，原任务 deadline 不延期。旧轮没有相同恢复协议，不能把旧新恢复数直接当因果提升。

前两次试运行分别因验收边界缺陷、仅凭名称推断计数器口径的过严评测规则而中止，原日志保留在 `2026-10-17-aiops2022-round3`／`round3b` 并标记排除。正式运行使用修复后一次冻结的 `2026-10-17-aiops2022-round3c`，不复用中止运行的结果。具体结果与审计见 [第三轮公开案例比较](../evaluations/public-rca/comparison-round3.zh-CN.md)。


## 最终观察

新 Cairn 对象＋类别联合正确率仍为 2/4，对象命中 3/4；四例均 completed、文件契约与声明数值复算通过，仍有两次语义错误完成。相对旧轮，完成数 2→4、超时 2→0，合计耗时 2345.95→1657.67 秒，但错误完成绝对数仍为 2。总用量 2294918 tokens，旧轮为至少 1819406，计费单价未知，不能宣称成本下降。

同轮 Pi 联合正确 4/4，其中一例输出预算停止时已保存正确答案但缺报告；新会话在 142.78 秒、83480 tokens 内补齐交付。Cairn 没有自然停止样本，实际超时恢复率未测得。四份真实状态副本重开接管检查 4/4 通过，context 8157–10083 字节、旧验收不复用、原数据库不变；四例 handoff 均在收尾保存，中途恢复收益尚待验证。

工程结论是保留这两项通用机制，同时明确验收 scope：文件与数值可复核解决交付可信度，根因语义还需要对象层级、替代解释和反证审查。本轮没有加入专门的 RCA 核心规则或常驻审查模型。
