## 原版回查

原版 scheduler 在新 fact、新 hint、open intent 从有到无后触发 reason，相同图状态跳过重复 reason。reason 先检查 Goal／偏航／线索覆盖；未完成又没有开放方向时，contract 要求给出下一方向。explore 只提交增量事实或结束当前方向，不能宣告整个目标完成。对应原版 `scheduler/loop.py:328,704`、`prompts/default/reason.md:15,31`、`contracts.py:93`、`prompts/default/explore.md:18`。

当前保留了 Finding 状态／历史、共同前提、条件覆盖、租约、重开、收尾及文件验收，但缺少把这些状态送回原生探索过程的闭环。此次移植行为语义，不恢复独立 worker、容器和常驻调度器。短任务仍允许直接完成。

原版 `server/routers/projects.py:257` 的 complete 只验证来源 fact 存在且非 goal，再写完成关系。Fact 没有独立语义评分或可执行反证规则；相关质量要求主要来自提示词。不能把原版的完成标志解释为独立正确性证明。

前一轮冻结实现已保存在本地 run3c 的 `implementation.before-round5`，全部 35 项实现哈希与旧 manifest 相符；历史比较不会被当前代码覆盖。


## 已落地行为

- checkpoint 回执的 `exploration` 返回短黑板：未覆盖条件、近期发现、未决假设、已排除方向、开放工作、问题和下一动作；原生 curated 工具结果在超过 60 秒未保存或收到新 hint 后，可附带一次去重的保存／回看提醒。提醒不记录工具元数据，不强制拦截、不启动额外模型，临近提交时由收尾提示优先。
- 支持 `finish {}` 复用既有覆盖；短任务可用 `summary+basis/references`；`summary+from` 只能消费已有、有依据的 supported Finding，不能引用工作项或待验证假设。摘要单独仍不创建证据；多条件不自动全覆盖。
- 宿主明确列出的必需文件在 finish 自动计算提交快照，不扫描目录、不猜测文件。captured／emergency、owner fencing、文件变化复验仍生效。
- UI 顶部、任务卡和报告分别呈现流程、文件／契约验收与结论审查。独立审查通过 `Engine.assess` 由可信宿主／人工写入，非公共 Agent 工具，绑定候选 proof 和 epoch；内容或 owner 变化后显示过期。没有审查时显示未评定。历史十二例的独立评分仅追加到 UI 副本，不改原始运行库。
- 关系图把 supported 标为“模型判断有支持”，把任务终点标为“流程已完成 · 结论另行审查”。修复 hashchange 导航，避免地址已换而仍展示旧任务。

## 冻结前运行缺陷与排除

初次真实运行暴露自动收集在内部 finish 重试时丢失 Artifact.description；文件未变，元数据变化却使刚通过的 proof 失效。先补用例复现同一 verified finish 返回 incomplete，再修复为保留已有清单顺序及描述，235 项完整回归与本地 Pi 探索夹具通过。同步补齐“获得新事实后恢复黑板回看、仅改进度措辞不触发新一轮回看”的去重回归。

初次 run4 的三段运行全部排除，耗时 1041.04 秒、至少 1096745 tokens，不作为正式单例替补。原始日志／冻结实现／失败原因完整保留；run4b 已以新工作区完整重跑八轮。
