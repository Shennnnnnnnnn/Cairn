# 即时状态与原生生命周期：真实 Codex 样例

适用于 Cairn 4.5。输入是合成离线报价材料，实际使用本机 Codex CLI 0.162.0、用户已配置的 gpt-6.1-sol 模型执行排查、修改和验证；不是预先写入的动画事件。

## 生成并运行

在 Cairn 仓库中生成一个新目录：

```sh
node scripts/prepare-state-example.mjs --root /tmp/cairn-regional-quote
cairn install --target codex --root /tmp/cairn-regional-quote
cd /tmp/cairn-regional-quote
export CAIRN_DB=/tmp/cairn-regional-quote/.cairn/state.db
codex
```

选择不存在的目录，生成器不会覆盖已有数据。在正常 Codex 会话中完成项目和 Cairn hooks 的信任。安装默认不改变模型设置。

向 Agent 输入：

> 使用 Cairn 排查本目录的地区报价串价。读取 README、fixtures 和复现脚本，实际复现，修复 quote.mjs，验证两个地区、不同请求顺序与真实缓存重复命中，并生成中文 report.md，明确合成输入和验证范围。自主决定调查方向和是否使用只读子 Agent；主会话继续推进自己的工作。使用现有工具，不记录工具调用。原生子会话生命周期由 Cairn hooks 自动保存，不需要你或子 Agent 转述 ID 和开始／返回。每次业务分支、执行项或结论变化立即用 cairn_update 单独保存；检查助手结果之前先保存 reviewing，接受后保存 completed。不等阶段总结批量补录。

另一个终端打开看板：

```sh
cairn ui --db /tmp/cairn-regional-quote/.cairn/state.db
```

普通 MCP／Multica 可以运行相同业务流程；缺少原生生命周期时由 Agent 即时报告未覆盖的业务状态，看板保留其来源，不声称宿主已确认。

## 原生执行和业务分支如何对应

“宿主执行会话”来自实际生命周期，即使没有业务分支 ID 也立即显示。它不代表额外增加了一个排查方向。宿主路由名可能是 `/root/data_audit`，hook ID 则是 UUID；名称、数量和时间接近均不足以自动证明两者对应。已知确切原生身份时可以关联，否则分别展示执行事实与业务状态，避免猜测。

因此回放到约 01:11 时，已经能看到宿主会话返回，而主 Agent 尚未更新业务分支。这是事件直接保存与模型稍后处理结果的实际时间差。约 01:24 时主 Agent 的复核节点变橙黄；02:09 时复核完成变紫蓝，主会话修复分支仍在推进。无需等所有助手结束才开展独立工作。

## 实际修复与验证

原实现的缓存键只有 SKU，而查价还依赖 market，导致先请求地区的价格被另一地区复用。模型将键改为序列化的 `[sku, market]`。

- 原脚本：修复前 4/8 错误，修复后 0/8。
- 五种请求顺序，共 160 次调用全部通过。
- 其中 120 次重复请求禁止访问底层价格表，仍返回同一个缓存对象，验证实际命中缓存。
- 额外验证清空缓存使八个条目失效，以及未知地区和未知 SKU 报错。
- 主会话独立复核助手的价格预期；模型结束后，另一个终端再次运行 reproduce.mjs 与 verify.mjs，均通过。

复跑模型生成的修复验证：

```sh
node reproduce.mjs
node verify.mjs
```

本次未验证生产环境、并发、动态价格更新、缓存过期或任意参数类型。报告保留这些范围限制。

## 回放操作

点击 **▷ 回放**。默认 1× 对应真实记录间隔，可选 5×、10×、30×、60×；拖到任意时刻查看最近已知状态。原生执行节点、业务分支、复核节点分别保留来源和状态，蓝色轮廓高亮最近变化。回放不启动模型或工具，不改变历史记录。

自动化验收为隔离其他插件创建临时 Codex 配置，仅启用已审阅的 Cairn hooks，保持 workspace-write 沙箱；临时认证副本在运行结束后清除。普通使用仍走宿主的项目与 hooks 信任流程。
